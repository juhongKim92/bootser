기호 세 개

기호뜻
n동시 스레드 수. 스레드 풀 크기, 워커 수, 동시 요청 수 — 무엇을 늘리고 있는지 그 개수입니다
σ (시그마)직렬 비율. 아무리 스레드를 늘려도 한 번에 하나씩만 통과하는 구간의 비율. 락, 단일 커넥션, 순서 보장 큐 같은 것들이에요
κ (카파)일관성 비용. 스레드끼리 서로 조율하는 비용입니다 — 캐시 라인 무효화, 락 경합, 코히런시 트래픽. 스레드 쌍의 수만큼 늘어나서 n(n−1) 로 들어갑니다

σ 와 κ 는 제가 고른 상수가 아니라 손잡이입니다. 당신 시스템의 값은 부하 시험으로 적합시켜야 해요 — 이 페이지가 하는 일은 그 두 값이 정해지면 무슨 모양이 나오는가를 보여주는 것입니다.

이렇게 해보세요

1. 스레드 1개 — 출발점

n=1 · σ=5% · κ=없음(0) 처리량 1.00 · 응답시간 ×1.00

기준점입니다. κ 를 0 으로 두면 USL 이 Amdahl 과 정확히 같아져요 — 두 곡선이 겹칩니다. κ 가 0 이면 역행이 없습니다. 스레드를 늘리는 것이 언제나 이득이거나, 최소한 손해는 아닙니다.

2. 256개까지 늘린다 (κ=0) — 상한에 부딪힌다

n 1 → 256 (κ=0 그대로) 처리량 1.00 → 18.62 · Amdahl 상한 ×20.0 응답시간 ×13.75

스레드를 256배로 늘렸는데 처리량은 18.62배입니다. σ=5% 면 상한이 1/0.05 = 20배이고, 스레드를 무한히 늘려도 그 값을 못 넘어요. 여기까지가 Amdahl 의 법칙입니다 — 수익이 줄어들 뿐, 마이너스는 아닙니다. 응답시간은 이미 13.75배가 됐지만요.

3. 일관성 비용을 켠다 — 처리량이 3.24로 떨어진다

κ 0 → 0.001 (n=256 그대로) 처리량 18.62 → 3.24 · Amdahl 은 여전히 18.62 정점 n*=31 · 응답시간 ×79.03

같은 스레드 수인데 처리량이 5.7배 낮습니다. κ 는 스레드 쌍의 수만큼 드는 비용이라 n(n−1) 로 들어가고, n 이 커지면 이 항이 분모를 지배합니다. Amdahl 곡선(파란색)은 계속 오르고 USL(초록색)은 이미 꺾여 내려온 상태예요. 두 곡선이 갈리는 것을 보세요.

4. 정점으로 내린다 — 스레드를 8배 줄이고 처리량 2.8배

n 256 → 31 (= 정점 n*) 처리량 3.24 → 9.04 (2.79배) 응답시간 79.03 → ×3.43 (23배 개선)

스레드를 줄여서 처리량이 2.79배가 됐습니다. 그리고 응답시간은 23배 좋아졌어요. 이게 이 페이지의 핵심입니다 — 정점은 n* = √((1−σ)/κ) 로 계산됩니다. σ=5%, κ=0.001 이면 √(0.95/0.001) = 30.82 예요.

5. 정점을 조금 넘겨본다 — 처리량은 거의 그대로인데

n 31 → 64 처리량 9.04 → 7.82 (13% 하락) 응답시간 3.43 → ×8.18 (2.4배 악화)

처리량은 13% 밖에 안 떨어졌습니다. 처리량 대시보드만 보면 눈에 안 띄어요. 그런데 응답시간은 2.4배가 됐습니다. 정점 근처에서 두 지표가 어긋나기 시작합니다 — 처리량은 완만하게 꺾이고 응답시간은 급하게 오릅니다. 리틀의 법칙 때문이에요(아래).

6. 직렬 비율을 반으로 — 상한만 오르고 정점은 그대로

σ 5% → 2% (n=31 · κ=0.001) Amdahl 상한 ×20.0 → ×50.0 정점 n* 30.82 → 31.30 (거의 안 움직인다)

직렬 구간을 반으로 줄이는 것은 큰 작업입니다. 상한은 두 배 반이 됐어요. 그런데 정점은 30.82 에서 31.30 으로 0.5 밖에 안 움직입니다. 정점 식에서 σ 는 (1−σ) 안에만 들어가니까요. 몇 개까지 늘릴 수 있는가를 정하는 것은 σ 가 아니라 κ 입니다.

7. 일관성 비용을 5배로 — 정점이 절반 아래로

κ 0.001 → 0.005 (σ=5%) 정점 n* 30.82 → 13.78 · 최대 처리량 9.04 → 5.47

κ 가 5배가 되면 정점은 √5 배 작아집니다(제곱근이니까요). 그래서 14개 스레드가 최선이고, 그 이상은 손해예요. κ 를 줄이는 것이 스레드를 늘리는 것보다 먼저입니다 — 공유 상태를 없애거나, 샤딩하거나, 락을 쪼개는 일이 그것입니다.

두 식

이 페이지는 식 두 개만 씁니다.

Amdahl — S(n) = n / (1 + σ(n−1))
직렬 구간이 σ 면 아무리 늘려도 1/σ 를 못 넘는다. 수익이 줄어들 뿐 마이너스는 아니다.
USL — C(n) = n / (1 + σ(n−1) + κn(n−1))
여기에 κn(n−1) 이 붙는다. 스레드 쌍의 수만큼 드는 비용이라 n² 로 자라고, 어느 지점부터 분모가 분자를 앞지른다.

그 지점이 정점입니다. 미분해서 0 이 되는 곳을 풀면 n* = √((1−σ)/κ) 가 나와요. 손잡이를 돌려 보면 미터의 "정점" 값이 항상 이 식과 맞습니다.

응답시간이 먼저 무너진다

처리량과 응답시간은 리틀의 법칙으로 묶여 있습니다 — 동시에 n 개가 돌고 있고 처리량이 C(n) 이면, 하나가 걸리는 시간은 n / C(n) 입니다.

여기서 비대칭이 생깁니다. 정점을 넘어가면 분자 n 은 계속 커지는데 분모 C(n) 은 줄어듭니다. 그래서 응답시간은 두 배로 나빠져요.

처리량 −64% 에 응답시간 23배. 그래서 처리량 대시보드만 보고 있으면 이 상태를 "약간 나쁨" 으로 읽습니다. 사용자는 전혀 다른 것을 겪고 있어요.

리틀의 법칙이 이 사이트에 네 번째로 나옵니다 — 8번은 커넥션 풀 크기, 19번은 창×커넥션, 5번은 Receive Maximum, 이 편은 스레드입니다. 단위만 다르고 식은 같습니다.

이 편의 검산점은 수학이다

이 사이트의 다른 편들은 바깥에서 온 검산점이 있었습니다 — 논문의 두 번째 예시, RFC 가 인쇄한 표, man page 의 합계 같은 것들이요. 이 편은 다릅니다.

USL 은 명세가 아니라 적합 모델입니다. σ 와 κ 는 실측으로 적합시키는 값이고, 제가 정할 수 있는 게 아닙니다. 그래서 계수를 손잡이로 내놓고, 검증하는 대상을 계수가 아니라 식이 만드는 두 지점으로 뒀습니다.
무엇을 검산하나어떻게
Amdahl 상한1/σ. n 을 아무리 키워도 이 값을 넘지 않는지 — 전 조합에서 확인합니다
USL 정점√((1−σ)/κ). 그 정수 근처가 실제로 최댓값인지 — 1부터 256까지 전수로 확인합니다
κ=0 이면USL 이 Amdahl 과 정확히 같아야 합니다

그러니 이 페이지를 읽을 때 이렇게 보세요 — "내 시스템의 처리량이 몇이다" 가 아니라 "σ 와 κ 가 이러면 모양이 이렇게 된다". 숫자를 가져가는 게 아니라 모양을 가져가는 편입니다.

이 모델이 가정하는 것

가정깨지면 어떻게 되나
정상 상태부하가 일정하다고 봤습니다. 몰리는 구간은 27번이고, 무너진 뒤 안 돌아오는 것은 14번입니다
σ 와 κ 가 상수실제로는 부하에 따라 변합니다 — 락 경합은 스레드가 늘면 성질이 바뀌고, 캐시는 워킹셋이 커지면 갑자기 나빠집니다. 적합 구간 밖으로 외삽하면 안 됩니다
스레드가 균질모든 스레드가 같은 일을 한다고 봤습니다. 섞여 있으면 σ 가 하나로 안 잡힙니다
측정이 정직하다처리량과 응답시간을 제대로 재고 있다고 봤습니다. 폐루프 부하 생성기로 재고 있다면 25번의 문제가 이 위에 겹칩니다 — 정점을 넘은 상태를 아예 못 볼 수 있습니다

κ 를 줄이는 일공유 상태를 없애기, 샤딩, 락 쪼개기, 스레드 로컬. κ 를 반으로 줄이면 정점이 √2 배 올라갑니다 — 스레드를 늘리기 전에 이쪽이 먼저입니다
