## 게이트 — 자료 하나를 붙일지 정하는 기준

황금연휴를 붙이면서 정리했고 천문에서 한 번 더 확인된 넷이다. **넷을 다 통과해야 착수한다.**

1. **미래 날짜가 미리 확정되는가.** 갱신이 월 1회다. 자주 바뀌는 자료를 담으면
   "D-3" 이라고 띄워 놓고 실제로는 밀린 상태가 된다. 사이트가 조용히 거짓말을 한다.
2. **축이 맞는가.** 자리가 셋이다 — 국가축(204개 국가 페이지) · 전세계 공통축(첫 화면·하늘) ·
   이름축(/holiday/, 공휴일 이름 60가지). 셋 다 아니면 놓을 자리가 없다.
   **셋째 자리는 2026-09-03 에 생겼다** — 그전까지 둘뿐이라고 적어 두었는데, 이미 담긴
   자료를 다른 축으로 뒤집으면 자리가 하나 더 나온다는 것을 그때 알았다.
3. **키 없이 받을 수 있는가.** 키가 필요하면 빌드 타임에만 쓰고 Actions secret 에 둔다
   (생성물만 배포되므로 클라이언트에는 안 나간다). 다만 그때부터 갱신이 남의 사정을 탄다.
4. **검산점이 있는가.** ← **이게 실제로 갈랐다.**
   자료가 스스로 앞뒤가 맞는지 볼 방법이 있어야 한다. 황금연휴는 *"이 연휴가 우리가 담은
   공휴일에 걸려 있나"* 가 검산점이었고, 천문은 *"일본이 공휴일로 정한 분점"* 과
   *"음력 명절이 가리키는 삭"* 이었다. 그게 없으면 `check-pages` 가 볼 것이 "받은 대로
   찍혔나" 뿐인데, 그건 아무것도 검사하지 않는 것과 같다.

   **덧 — 착수 전에 4번부터 잰다.** 국제 기념일과 스포츠 대회를 이 순서로 걸러 냈다.
   짓고 나서 "검산할 게 없네" 를 발견하면 이미 늦다. 재는 데 반나절, 짓는 데 이틀이다.

   **덧 — 검산점은 종류도 봐야 한다.** 천문에서 21개 지점을 다 맞히고도 ΔT 를 통째로
   빼먹은 것이 안 잡혔다. 공휴일 검산점이 *날짜*만 주기 때문이다. 자료가 날짜보다 잘게
   나뉘면(시각·수량) 그 단위로 견줄 점이 따로 있어야 한다.

     공통축에 이만큼 순수하게 맞는 자료가 없었다.
  3. **무키** — 계산이다.
  4. **검산점 — 재 봤다. 문다.** 착수 전에 4번부터 잰다는 원칙대로, 짓기 전에 확인했다.

  **검산점 넷.** 종류가 갈리는 것이 중요하다 — 천문에서 ΔT 를 통째로 빼먹고도 안 잡힌
  것은 공휴일 검산점이 *날짜*만 주었기 때문이다. 식은 **날짜 · 시각 · 수량** 셋 다 준다.

  - **삭망 표와의 짝** (날짜+시각) — 일식은 반드시 삭에, 월식은 반드시 망에 일어난다.
    이미 검증된 `sky.json` 의 `moons` 74건에서 짝이 안 나오면 계산이 틀린 것이다.
    2025~2027 의 식 12건이 **전부** 짝을 찾았다.
  - **γ 와 종류의 정합** (수량) — `|γ| < 0.9972` 면 중심식, `0.9972~1.5433+u` 면 부분,
    그 밖이면 식이 아니다. 종류와 γ 가 서로 어긋나면 어느 한쪽이 틀렸다.
  - **사로스 주기** (간격) — 같은 계열은 6585.3213일 뒤에 되풀이된다. 창을 앞뒤로
    넓혀 계산하면 계열별 간격이 이 값과 맞아야 한다. **ΔT 를 빼먹으면 여기서 물린다** —
    시각 단위 검산점이라 날짜만 보는 눈에는 안 걸리던 종류의 실수를 잡는다.
  - **식의 계절** (군집) — 식은 173.31일 간격으로 무리 지어 온다. 12건이 여섯 무리로
    갈리는지 본다.

  **잰 값** (2025~2027, Meeus 54 조건을 `sky.json` 의 삭망 표에 붙여 실측)

  식 **12건** — 일식 6 · 월식 6. 12건 전부 삭망 표에서 짝을 찾았다.

  | 날짜(UTC) | | 종류 | γ |
  |---|---|---|---|

  | 2025-03-29 | 일식 | 부분 | 1.042 |
  | 2025-09-07 | 월식 | 개기 | −0.276 |

  **표지 연도가 마침 좋다.** 자료 창 안에 큰 개기일식이 둘 있다 — 2026-08-12(그린란드·
  아이슬란드·스페인)와 2027-08-02. 뒤엣것은 γ 가 0.142 로 그림자 중심에 바짝 붙어
  개기가 6분대다. 두 해 다 표지 연도를 지나기 전에 온다.

  **범위를 그어야 한다.** *"어디서 몇 시에 몇 퍼센트 가려지나"* 는 Besselian elements 가
  필요해 무게가 다르다. **날짜 · 종류 · 최대식 시각(UTC/KST) · γ · 크기 · 대략적 관측
  지역**까지로 끊으면 계산만으로 끝난다. 지역은 γ 와 계절에서 위도대까지만 말하고
  나라 이름은 적지 않는다 — 적는 순간 검산점이 없는 자료가 된다.

  **자리** — `/sky/` 아래 여섯 번째 갈래다. 허브의 카드 줄과 첫 화면 하늘 칸이 지금
  넷(절기·삭·보름·유성우)인데, 식을 넣으면 다섯이 된다. `check-pages` 의
  *"하늘 칸이 4줄"* 검사가 그 수를 박아 두었으므로 같이 고쳐야 한다.

_여기 있던 「세계가 함께 쉬는 날」은 이름 축을 지으면서 그 부산물로 나왔다 —
위 「완료」 참고. 따로 지을 일이 아니었다._

**그때 배운 것 하나.** 이 문서는 여태 *"자료를 하나 더 받아올까"* 만 물었는데,
값어치 있는 후보 셋이 잇달아 **이미 담긴 자료를 다른 축으로 뒤집는 것**에서 나왔다
(이름 축 · 날짜 축 · 순위). 게이트 넷 가운데 3(무키)과 4(검산점)를 자동으로 통과하고,
1(확정성)도 원본 자료에서 물려받는다. **다음에도 밖을 먼저 보지 말고 안을 한 번 더 뒤집어 볼 것.**
남은 축 후보는 아래 「기존 것 보강」의 시간대뿐이고, 그건 자료가 아니라 계산이다.

**2026-09-04 에 그 뒤집기에 한 겹이 더 있는 것을 알았다.** *"우리가 담은 자료"* 만
뒤집을 게 아니라 **런타임이 이미 들고 있는 표**도 자료다 — `Intl` 의 `getWeekInfo()`
(요일 축의 나라별 주말)와 `-u-ca-` 달력 표(`/sky/calendar/`)가 그렇게 나왔다.
파일도 네트워크도 키도 늘지 않고, 게이트 3(무키)을 공짜로 통과한다. 대신 **받아 적은
값이라 검산점을 따로 세워야 한다** — 우리 계산과 견주거나, 손으로 적은 고정값과 견주거나,
같은 표에 다른 질문을 던지는 식이다. 다음에도 밖을 보기 전에 `Intl` 을 먼저 뒤져 볼 것.

  > 통과했던 근거 (Node 24.13 에서 실제로 돌려 본 것):
  > · `new Intl.Locale('und-KR').getTimeZones()` → `['Asia/Seoul']` — 204개국 전부 나온다
  > · `timeZoneName: 'longOffset'` 을 날짜별로 훑으면 전환일이 그대로 떨어진다
  > · 2026 에 전환이 있는 나라 61개. API 도 의존성도 필요 없다 (tzdata 가 Node 에 있다)
  >
  > **내린 이유 — 게이트 1번(미래 날짜가 미리 확정되는가)이 실은 안 통과한다.**
  > 서머타임은 *천문이 아니라 정치가 정하는 날짜*다. 미국은 상원을 몇 번 통과했고,
  > EU 는 2019년에 폐지 지침을 의결해 놓고 아직 시행하지 않았다. 규칙이 바뀌면 tzdata 가
  > 따라오고 생성기는 조용히 "전환 없음" 을 내는데, **그게 맞는 동작이라 아무도 못 알아챈다.**
  > 공휴일은 연 1회 확정되고 바뀌면 diff 에 보이지만, 이쪽은 나라 하나가 통째로 사라져도
  > 표가 비는 것으로만 나타난다.
  >
  > **자료를 담을 값어치보다 시간대 표가 값어치 있었다.** 이 항목을 파다 나온 진짜 소득은
  > `getTimeZones()` 이고, 그건 아래 「기존 것 보강」으로 옮겼다. 그쪽은 정치와 무관하다.
  >
  > **⚠ 사실 확인 메모.** 내릴 때 "미국이 서머타임을 폐지했다" 를 근거로 이야기했는데,
  > 확인해 보니 **Node 24.13 에 들어 있는 tzdata 2025b 는 아직 미국 전환을 담고 있다** —
  > `America/New_York` 2026-03-08 / 11-01, 2027-03-14 / 11-07. (전환이 없는 것은
  > `America/Phoenix` · `Pacific/Honolulu` 처럼 원래 안 하던 곳이다.)
  > 폐지가 확정됐다면 tzdata 를 최신으로 올려 다시 확인할 것. 다만 **내린 판단 자체는
  > 미국과 무관하게 선다** — 61개국 대부분이 유럽이고, 위의 "정치가 정한다" 가 본 이유다.

  나라마다 지금 날짜가 다른 것은 그대로다.

  자료 정합성 검사가 페이지 순회 안에 있어서 ko/en 두 번 돈다. 값싼 검사라 일부러 그렇게
  두었지만(두 페이지가 같은 자료를 봤다는 뜻이 된다), 자료 검사가 더 무거워지면 밖으로 뺀다.

## 자료를 하나 더 붙일 때 손대는 곳

황금연휴와 천문에서 실제로 건드린 곳 전부다. 하나라도 빠지면 조용히 반쪽이 된다.

- [ ] **축이 셋으로 늘었다 — 국가 · 전세계 공통 · 이름.** 이름 축처럼 **자료가 페이지
  수를 정하는** 축이면 슬러그를 `EXTRA` 에 손으로 적지 말 것. `config.mjs` 의
  `NAME_PAGE` 처럼 모양으로 걸고 `kindOf` 에 갈래를 하나 더한다. 손으로 적으면 자료가
  바뀔 때 조용히 어긋난다. 뿌리(`holiday`)만 `EXTRA` 에 있으면 청소가 하위까지 지운다.
- [ ] **국가 축인가 공통 축인가부터 정한다.** 공통 축이면 `config.mjs` 의 `EXTRA` 에
      슬러그를 넣고(두 글자 금지 — 국가 코드와 부딪힌다) `check-pages` 의 갈래를 늘린다.
- [ ] **받아 오는 자료면 `gen-holidays.mjs`** — 받고, 거르고, **버린 건수를 찍는다.**
      조용히 사라지면 다음 달에 왜 줄었는지 알 수 없다.
      **계산하는 자료면 `gen-sky.mjs` 처럼 따로 둔다** — 네트워크 단계와 섞지 않는다.
- [ ] **검산점을 정한다** — 게이트 4번. 황금연휴의 "공휴일에 걸려 있나" 에 해당하는 것.
- [ ] **`gen-pages.mjs` 의 `L.ko` / `L.en`** — 페이지 문안 두 벌
- [ ] **`dday.js` 의 `STR.ko` / `STR.en`** — 화면에서 바뀌는 문안 두 벌
- [ ] **자료가 낡으면 멈추게 한다.** `gen-pages` 가 `data.long` 이 없으면 종료 코드 1 을
      내는 것처럼. 섹션 하나가 조용히 빠지는 게 가장 알아채기 어렵다.
- [ ] **`harness.mjs`** — 새 행 모양을 파싱해 준다. 안 하면 `check-pages` 가 "그려진 결과" 를
      되읽지 못하고 HTML 문자열만 보게 된다.
- [ ] **`check-pages.mjs` 의 기대값을 따로 적는다.** `dday.js` 의 함수를 가져다 쓰면
      아무것도 검사하지 않는 것과 같다 — 번역이 통째로 틀려도 통과한다.
- [ ] **CSS 계약을 `check-pages` 에 박는다.** 화면으로만 확인되는 것은 하니스가 못 본다.
- [ ] **표 머리 글자까지 검사한다.** 칸수만 세면 시각이 없는 표에 "날짜와 시각" 이라고
      적혀 있어도 통과한다 (`/sky/calendar/` 에서 걸린 자리다).
- [ ] **검사 범위를 자료 범위에 맞추지 않는다.** 규칙에 갈래가 둘이면 **두 갈래가 다
      걸리는 범위**까지 넓힌다. 계산이 순수 함수면 공짜다 — 노루즈는 자료 3년 ·
      검사 31년이고, 한 갈래가 0 번 걸리면 그 자체로 실패하게 해 둔다.
- [ ] **영어 누출.** 누출 검사는 `<td class="name">` 을 면제한다(공휴일 이름은 현지어라서).
      **우리가 쓰는 말은 그 클래스를 쓰면 안 된다** — 황금연휴 칸을 `class="len"` 으로 둔 이유다.
- [ ] **일부러 깨뜨려 검사가 무는지 본다.** 자료 한 칸 밀기 · 규칙 위반 심기 · CSS 규칙 지우기 ·
      계산 1 틀리기. 안 물면 그 검사는 없는 것이다.
- [ ] **배포 순서** — `gen-holidays` → `gen-globe` → `gen-pages` → **commit** → `gen-sitemap` → `check-pages` → push.
      commit 이 먼저여야 `lastmod` 가 맞는다. `sitemap.xml` 은 `--amend` 로 같은 커밋에 합친다.
      `gen-globe` 는 `countries.json` 이 바뀔 때만 돌리면 된다 — 나라가 늘면 점이 없다며 멈춘다.
