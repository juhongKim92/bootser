## 완료

- [x] **공유 카드** — `og:image` · `twitter:card` (2026-09-02)

  > 412개 페이지 전부 0이던 것을 채웠다. 카드 206장(첫 화면 · 하늘 · 국가 204),
  > 합계 **1,248 KB · 평균 6.1 KB · 가장 큰 것 7.7 KB**. 예상(2.5 MB)의 절반이다 —
  > 단색 블록뿐이라 deflate 가 잘 먹는다.
  >
  > **한글은 이미지에 못 들어간다.** 래스터라이저가 없으니 폰트를 못 읽는다. 그런데
  > 카드에 들어갈 글자를 재 보니 **31자뿐**이었다 — `countries.json` 의 영어 이름을
  > NFD 로 정규화하면(Å→A · ô→O · ç→C) `A-Z` 와 ` ( ) , -` 만 남고 국가 코드는 애초에
  > 순수 A-Z 다. 31자는 손으로 찍을 수 있는 양이라 5×7 픽셀 글꼴을 원화로 두었다.
  > 한국어 국가명은 `og:title` 이 나른다 — 미리보기는 이미지 옆에 제목을 같이 보여준다.
  >
  > **`public/og/` 는 함정이었다.** `gen-pages.mjs` 의 청소가 `/^[a-z]{2}$/` 인
  > 디렉터리를 지우는데 `og` 가 정확히 두 글자다. 거기 뒀으면 **빌드마다 조용히
  > 사라졌다.** `public/card/` 로 갔고, `gen-card` 와 `check-pages` 양쪽이 이름이
  > 두 글자가 되는 순간 멈춘다.
  >
  > **카드에 자료를 넣지 않았다.** 공휴일 수나 연도를 그리면 매월 갱신 워크플로가
  > 206개 PNG 를 다시 쓰고 바이너리가 git 이력에 영원히 쌓인다. 카드는 신원만
  > 나르고, 그래서 국가 목록이 바뀔 때만 달라진다.
  >
  > **PNG 인코더를 `png.mjs` 로 뗐다.** 파비콘과 카드가 두 벌로 들고 있으면 갈라진다.
  > 리팩터링이 출력을 바꾸지 않았다는 것은 `gen-favicon.mjs --check` 가 증명한다 —
  > 커밋된 파비콘 넷과 **바이트 단위로 같다**.
  >
  > **일부러 깨뜨려 다섯 다 물렸다.** 카드 파일 지우기 · 유령 카드 심기 ·
  > IHDR 크기 바꾸기 · 페이지에서 `og:image` 지우기 · 원화의 글자 비우기.
  >
  > **1200×630 을 `check-pages` 에 따로 적었다.** `card-art.mjs` 에서 들여오면 둘이
  > 같이 틀려도 통과한다. 페이지 쪽은 HTML 에 적힌 수를, 파일 쪽은 PNG 머리의 수를
  > 본다 — 갈라지면 한쪽에서 걸린다.
  >
  > **남은 것** — 배포 뒤 카카오톡·트위터·슬랙에 실제로 던져 카드가 뜨는지 본다.
  > 하니스가 볼 수 없는 유일한 지점이다(캐시는 각 플랫폼이 따로 들고 있다).

## A급 — 코드에서 재 봤고, 칸이 비어 있다

### 1. 사이트의 유일한 차별점(D-day)이 HTML 에 없다

- [ ] 연 단위로 확정되는 사실을 정적 텍스트로 박는다

  > title 에 "D-day" 라고 적어 놓고 정작 HTML 은 이렇다:
  >
  > ```html
  > <dt>다음</dt><dd id="next"><em>계산하는 중…</em></dd>
  > <dt>다음 연휴</dt><dd id="break"><em>계산하는 중…</em></dd>
  > ```
  >
  > 구글이 JS 를 렌더하긴 하지만 렌더 큐는 며칠씩 밀리고, **스니펫은 대개 원본 HTML
  > 에서 뽑는다.** 클릭을 만드는 것이 스니펫인데 거기 들어갈 문장이 없다.
  >
  > **게이트 1번을 지킨다.** 날짜에 따라 변하는 것(D-day · 오늘 여부)은 그대로 브라우저에
  > 둔다. 대신 **연 단위로 확정되는 것**만 박는다 — 공휴일 수, 가장 긴 연휴의 길이와
  > 이름과 구간, 주말과 겹치는 날 수. 전부 `data/{CC}.json` 과 `long` 에서 나온다.
  > 새로 받아 올 것이 없다.
  >
  > **검사도 같이 간다.** 박은 문장이 자료와 갈라질 수 있으므로 `check-pages` 가
  > 표를 세어 그 문장과 견딘다. `dday.js` 의 함수를 가져다 쓰면 아무것도 검사하지
  > 않는 것과 같다는 원칙은 여기도 그대로다.

### 2. description 의 뒷문장이 204개 페이지에서 같다

- [ ] 국가별로 실제 다른 사실을 description 에 넣는다

  > 앞부분(국가명·숫자)만 다르고 **뒷문장은 204개가 전부 같다.**
  > `…의 공휴일 N일을 날짜순으로. 다음 공휴일까지 남은 날을 함께 보여줍니다.`
  >
  > 이러면 구글이 무시하고 본문에서 스니펫을 자체 생성한다. **CTR 통제권을 잃는다.**
  >
  > **1번과 같은 재료다.** 가장 긴 연휴 이름·길이를 문장으로 만들어 두면 화면과
  > description 에 같이 쓴다. 두 항목을 따로 하면 같은 계산을 두 번 짠다.
  >
  > **`gen-pages.mjs` 의 `L.ko` / `L.en` 두 벌**을 건드리므로, `docs/todo.md` 의
  > 「기존 것 보강 — 국가별 시간대」와 손대는 파일이 겹친다. 같이 처리하면 문안 두 벌과
  > 검사 재작성이 한 번으로 끝난다.

### 3. `/sky/` 가 최대 기회인데 한 URL 에 176건이 다 몰려 있다

- [ ] `/sky/meteor/` · `/sky/term/` · `/sky/moon/` 으로 축을 쪼개고 `/sky/` 는 허브로

  > **여기가 실제로 이길 수 있는 판이다.** 공휴일은 timeanddate·publicholidays 같은
  > 거대 도메인이 이미 먹었지만, **한국어 절기·유성우는 그들이 안 다룬다.**
  >
  > 유성우는 검색 수요가 극단적으로 스파이크한다 — 페르세우스 8월, 쌍둥이자리 12월,
  > 사분의자리 1월. 절기도 입춘·하지·동지가 각각 수요를 갖는다. 그런데 지금은 한 페이지가
  > 셋을 다 이고 있어서 **어느 쿼리에도 정확히 대응하지 못한다.**
  >
  > **게이트를 다시 통과할 필요가 없다** — 새 자료가 아니라 이미 검증된 `sky.json` 의
  > 축 분리다. `data/` 도 안 커진다.
  >
  > 손대는 곳은 `docs/todo.md` 의 「자료를 하나 더 붙일 때」와 같다:
  > `config.mjs` 의 `EXTRA` 에 슬러그 셋(**두 글자 금지** — 국가 코드와 부딪힌다),
  > `check-pages` 의 갈래, `gen-sitemap`, `gen-pages` 의 문안 두 벌.
  >
  > **국가 페이지에서 `/sky/` 로 가는 링크가 없다.** 첫 화면에 딱 하나뿐이다.
  > `/sky/` 계열을 넷으로 늘릴 거면 국가 페이지 아래에 한 줄 넣는다.
  >
  > 개별 이벤트 페이지(`/sky/meteor/perseids/`)까지 갈 수 있지만 **GSC 데이터를 보고
  > 정한다.** 먼저 셋으로 쪼개고, 어느 것이 실제로 노출되는지 본 다음이다.

## 기대치를 낮춰 둘 것 — 여기 시간을 쓰지 않는다

- **구조화 데이터로 리치 결과를 노리는 것.** 공휴일 표에 `Event` 를 붙여도 거의 안 나온다
  — 구글 Event 리치 결과는 장소·티켓이 있는 이벤트 대상이다. 값어치 있는 것은 첫 화면의
  `WebSite` + `ItemList` 정도(사이트링크)고, 그건 **첫 화면에 ld+json 이 아예 없다**는
  사실을 메우는 김에 같이 한다. 그 이상은 없다.
- **head term.** "2026 공휴일" 류는 신생 도메인이 이길 수 없다. 이 문서의 모든 항목은
  롱테일과 CTR 이 목표지 head term 이 아니다.
- **과거 연도(2025) 표를 지우는 것.** 문맥으로 값어치가 있고, `config.mjs` 주석에 적힌
  이유(12월 말·1월 초에 칸이 비는 것)가 그대로 유효하다. 건드리지 않는다.
