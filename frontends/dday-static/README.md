# dday-static — this is the day

204개국 공휴일과 황금연휴, 공휴일 이름별 모음과 나라별 순위, 그리고 절기·삭망·유성우·음력을
한국어·영어로 보여주는 정적 사이트.
**백엔드도 빌드 도구도 의존성도 없다.** `public/` 을 Cloudflare 에 그대로 얹는다.

`apps/d-day/d-day-service` 와는 별개다. 저쪽은 회원·영화·스포츠까지 다루는 Spring 서비스로
그대로 남아 있고, 여기는 공개 공휴일(`PUBLIC_HOLIDAY`)만 떼어 낸 읽기 전용 사이트다.

## 왜 서버가 없어도 되나

남은 외부 의존이 [Nager.Date](https://date.nager.at/) 하나뿐이고 API 키가 없다.
공휴일은 연 단위로 확정되는 자료라 요청마다 계산할 것이 없다 — 빌드 타임에 받아
JSON 으로 굳히고, 날짜에 따라 달라지는 것(D-day · 오늘 여부)만 브라우저가 계산한다.

| 서버가 하던 일 | 어디로 갔나 |
| --- | --- |
| Nager 호출 → DB 저장 | `tools/gen-holidays.mjs` (빌드 타임) |
| 연휴 구간 계산 | Nager `LongWeekend` — 같은 빌드 단계 |
| 천문 계산 | `tools/astro.mjs` — 네트워크조차 안 탄다 |
| 이름·날짜·순위로 묶기 | `tools/gen-pages.mjs` (빌드 타임, 새로 받는 것 없음) |
| `LocalDate.now(timezone)` | 브라우저 — 기기 날짜 |
| 다음/지난 공휴일 탐색 | 브라우저 — `dday.js` 의 `classify()` · `classifyBreaks()` |
| Redis 캐시 | Cloudflare CDN |

## 로컬에서 보기

### `index.html` 을 그냥 열면 CSS 가 하나도 안 붙는다

고장이 아니다. 자산 링크가 전부 절대경로(`/shared/base.css`)라서 `file://` 로 열면
드라이브 루트(`C:sharedase.css`)를 뒤진다. 페이지가 `/` · `/kr/` ·
`/holiday/christmas/` 처럼 깊이가 다른 자리에 놓이므로 상대경로로 둘 수 없다 —
깊이마다 `../` 를 다시 세야 하고, 그러면 생성기가 페이지마다 다른 링크를 찍어야 한다.

**정적 서버로 띄우면 된다.** 저장소 루트에서:

```bash
npm run dev:dday-static
```

이 디렉터리 안에서라면 같은 것을 직접 부른다.

```bash
node tools/serve.mjs                # http://localhost:8000
node tools/serve.mjs --port 8001    # 포트가 이미 잡혀 있을 때
```

의존성은 없다 — node 내장 모듈만 쓴다. `npm install` 도 필요 없다.
(다른 프런트엔드의 `dev:*` 는 `npm run dev -w @booster/...` 로 워크스페이스에
넘기는데, 여기는 `package.json` 이 없어서 워크스페이스 구성원이 아니다.
그래서 루트 스크립트가 `node` 를 직접 부른다 — 일부러 그렇게 두었다.)

### 켜고 끄기

| | |
| --- | --- |
| 켜기 | 터미널에서 위 명령. 그 창은 서버가 도는 동안 붙잡혀 있는 게 정상이고 요청 로그가 찍힌다 |
| 끄기 | 그 창에서 **Ctrl+C** |
| 창을 잃어버렸을 때 | 아래 PowerShell 한 줄 |

```powershell
# 누가 8000 을 잡고 있나
Get-NetTCPConnection -LocalPort 8000 -State Listen | Select-Object OwningProcess

# 죽이기
Get-NetTCPConnection -LocalPort 8000 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

창을 따로 안 열고 떼어 놓으려면 `Start-Process node -ArgumentList 'frontends/dday-static/tools/serve.mjs' -WindowStyle Hidden`
로 띄우고 위 명령으로 죽인다. 포트가 이미 잡혀 있으면 서버가 그 사실과 함께
죽일 명령까지 찍고 멈춘다.

| | |
| --- | --- |

### 배포와 무엇이 같고 무엇이 다른가

- **같다 — 404 흐름.** `wrangler.toml` 의 `not_found_handling = "404-page"` 를 흉내 내
  경로를 거슬러 올라가며 가장 가까운 `404.html` 을 쓴다. 언어 칸마다 404 를 하나씩
  둔 것이 실제로 맞는지 여기서 확인된다 — python 의 `http.server` 로는 볼 수 없다.
- **다르다 — `_headers`.** 글꼴 `immutable` 같은 캐시 머리는 안 붙는다. 오히려 반대로
  `Cache-Control: no-store` 를 붙인다. 고친 CSS 가 브라우저 캐시에 걸려 "왜 안 바뀌지"
  로 시간을 버리는 쪽이 훨씬 잦다.
- **다르다 — 비콘.** `inject-beacon.mjs` 는 빌드 단계에서만 돈다.
- `serve.mjs` 는 **Cloudflare 빌드 명령에 없다.** 빌드가 돌리는 것은 `check-pages` 와
  `inject-beacon` 뿐이다.

### 화면을 고친 뒤

HTML·CSS 를 고쳤으면 새로고침만 하면 된다. 다만 **`gen-pages.mjs` 의 템플릿을 고쳤으면
다시 돌려야** 하고(`public/` 의 HTML 은 생성물이다), CSS 규칙 이름을 바꿨거나 지웠으면
`check-pages` 의 **CSS 계약**(아래 「검사」 15·16번)이 문다 — 그건 화면으로만 확인되는
것을 검사가 붙들고 있는 자리이므로, 규칙을 옮겼으면 그 목록도 같이 옮긴다.

```bash
node tools/gen-pages.mjs && node tools/check-pages.mjs
```

## 자료 갱신

**매월 1일 03:00 UTC 에 GitHub Actions 가 알아서 한다** —
`.github/workflows/dday-static-refresh.yml`.

Nager.Date 를 호출하는 유일한 자동 경로다. Cloudflare 빌드에서는 부르지 않는다 —
빌드마다 1224번(204개국 × 3년 × 공휴일·연휴) 치면 자료가 조용히 바뀌어 배포된다.

워크플로가 하는 일은 아래 손 절차와 똑같고, **순서가 중요하다.**

```bash
cd frontends/dday-static

node tools/gen-holidays.mjs    # 1. Nager 에서 자료를 새로 받는다 (유일한 네트워크 단계)
node tools/gen-sky.mjs         # 2. 절기·삭망·음력을 다시 계산한다 (네트워크 없음)
node tools/gen-pages.mjs       # 3. 자료로 HTML 을 다시 만든다 (이름 축·순위도 여기서 묶인다)
node tools/gen-card.mjs        # 3.5. 국가 목록이나 이름 축 원화가 바뀌었으면 공유 카드도
node tools/gen-fonts.mjs       # 3.6. 새 글자가 들어왔으면 글꼴 조각도 (네트워크)
node tools/gen-flags.mjs       # 3.7. 국가 목록이 바뀌었으면 국기도 (네트워크)
git add -A && git commit       # 4. lastmod 가 여기서 정해진다
node tools/gen-sitemap.mjs     # 5. sitemap.xml
node tools/check-pages.mjs     # 6. 실패하면 밀지 않는다 (종료 코드 1)
git push                       # 7. 나머지는 Cloudflare 가 한다
```

4번을 건너뛰면 모든 HTML 이 "커밋 안 된 수정본" 으로 판정돼 `lastmod` 가 죄다 오늘이
된다. 구글은 `lastmod` 가 부정확하면 아예 무시하므로 그게 최악이다. 5번이 4번 뒤에
오므로 `sitemap.xml` 이 커밋 밖에 남는데, 워크플로는 `--amend` 로 같은 커밋에 합친다.

워크플로에서 특히 조심한 것 둘.

- **`fetch-depth: 0`** — `gen-sitemap.mjs` 가 파일마다 `git log -1` 로 `lastmod` 를
  뽑는다. 얕은 클론이면 이력이 없어 전부 오늘로 찍힌다.
- **급감 방어** — `gen-holidays.mjs` 는 `data/` 를 통째로 지우고 새로 쓴다. Nager 가
  잠시 절반만 돌려주는 날이면 국가 페이지 100개가 조용히 사라지는데, 1:1 대응은
  그대로라 `check-pages` 도 통과한다. 그래서 직전 국가 수의 90% 미만이면 아무것도
  쓰지 않고 멈춘다. 진짜로 줄어든 것이라면 `--allow-shrink`.

자료가 그대로인 달에는 아무것도 커밋하지 않는다 — 생성기가 결정적이라 같은 입력이면
바이트까지 같은 출력이 나온다.

주기가 **월 1회**인 이유. 공휴일은 사실상 연 1회 바뀌고 3년치(작년·올해·내년)를 담고
있어 연말연시에도 "다음/지난" 이 비지 않는다. 다만 해가 바뀌면 국가 페이지의 표지
연도가 갱신돼야 하므로(`MID = YEARS()[1]`) 방치하면 계속 지난 해로 남는다.

## Cloudflare 프로젝트 설정

Workers Builds 가 push 를 받아 배포한다. 설정 네 칸이 전부인데, **backend-internals
프로젝트 설정을 복사해 오면 둘 다 틀린다** — 실제로 그래서 두 번 깨졌다.

| 칸 | 값 | 틀리면 |
| --- | --- | --- |
| Root directory | `frontends/dday-static` | 저장소 루트가 npm workspace 라 wrangler 가 "run in the root of a workspace" 로 멈춘다 |
| Build command | `node tools/check-pages.mjs && node tools/inject-beacon.mjs` | backend-internals 는 `node inject-beacon.mjs` (루트, tools/ 아님) 라 `MODULE_NOT_FOUND` |
| Deploy command | `npx wrangler deploy` | |
| 환경 변수 | `CF_BEACON_TOKEN` | 없으면 비콘만 안 들어가고 배포는 된다 |

빌드 명령에 검사를 물려 두었으므로 **깨진 페이지는 배포되지 않는다.**
`inject-beacon.mjs` 는 검사 뒤에 와야 한다 — 커밋된 HTML 을 제자리에서 고치기 때문에
먼저 돌리면 546개가 전부 수정본이 된다.

빌드 단계에서는 `gen-holidays` · `gen-sky` · `gen-pages` 를 돌리지 않는다. 생성물이 이미 커밋돼
있고, 빌드 때마다 Nager 를 1224번 치면 자료가 조용히 바뀌어 배포될 수 있다.
자료 갱신은 위 절차대로 손으로 하고 diff 를 보고 넘긴다.


**따뜻한 색을 한 곳에만 쓴다.** `--today` 하나뿐이고 나머지는 전부 찬색이다.
그래서 표에서 오늘이 어디인지가 색만으로 잡힌다 — 이 사이트의 유일한 강조다.

**`--today` 를 옮기면 브랜드도 따라가야 한다.** 파비콘과 공유 카드의 강조색은
`tools/favicon-art.mjs` 의 `ACCENT` 이고 그것이 곧 `--today` 와 같은 뜻이다.
여기만 두고 가면 파비콘·카드는 주황인데 화면의 오늘은 라즈베리인 사이트가 된다.
같이 옮기고 `gen-favicon` · `gen-card` 를 다시 돌렸다.

`TILE`·`MARK` 는 **어두운 테마의 `--paper`·`--ink`** 를 쓴다. 밝은 쪽이 아닌 이유는
파비콘이 밝은 탭 바에 놓이기 때문이다 — 어두운 타일이어야 실루엣이 산다.

backend-internals 와는 이제 계열이 갈린다. 저쪽은 따뜻한 종이색 그대로다.

## 축 탭

축이 넷이 되면서(국가 · 순위 · 이름 · 하늘) 첫 화면에 「다른 축으로 보기」 칸을 두는
것으로는 모자랐다. 그 칸은 첫 화면에만 있어서 **국가 페이지에서 순위로 가려면 첫
화면을 거쳐야 했다.** 그래서 모든 페이지 머리말로 올리고 그 칸은 없앴다 — 같은 링크를
두 군데 두면 어느 쪽이 정본인지 모르게 된다.

지금 보는 축은 `aria-current="page"` 와 `.tab.here` 로 함께 표시한다. **색만으로
가르지 않는다** — 굵기까지 달라야 색을 못 보는 눈에서도 읽히고, 보조기술에는 색이
아무것도 전달하지 않는다.

좁은 화면에서는 접지 않고 **옆으로 굴린다.** 접으면 머리말이 두 줄이 되는데 그건
sticky 라 화면 위쪽을 계속 먹는다. 640px 아래에서는 상표를 감춰 자리를 비운다 —
탭의 첫 칸이 첫 화면으로 가므로 길이 끊기지 않는다.

`check-pages` 가 페이지마다 본다: 탭이 넷인가 · 잡힌 것이 하나인가 · 그 하나가 이
페이지의 축인가 · `aria-current` 가 붙어 있나 · 네 링크가 같은 언어 칸인가.

## 국기

이모지였다. **윈도우에서는 국기로 그려지지 않는다** — 크롬·엣지가 지역 표시 기호
두 개를 한 글리프로 합치지 않아서 `GH` 라는 두 글자 상자로 보인다. 국내 방문자
대부분이 윈도우인데 그 화면에서는 국기가 아예 없었던 셈이다.

그래서 `flag-icons`(MIT)의 4x3 SVG 를 **우리 오리진에 들였다.** 글꼴에서 한 것과
같은 판단이다 — 남의 오리진을 물지 않고, 받은 바이트를 그대로 커밋하고, 고지를 함께
실어 나르고(`/flags/LICENSE.txt`), 검사가 무결성을 본다.

| | |
| --- | --- |
| 개수 | 204개 — `countries.json` 의 코드 전부가 upstream 에 있다 (코소보·스발바르까지) |
| 무게 | 합계 1,406 KB · 평균 6.9 KB |
| 무거운 것 | RS 180 KB · BO 109 KB — 국장이 든 국기다 |
| 판 | `flag-icons@7.2.3` 으로 박아 둔다 |

**목록은 `loading="lazy"` 로 건다.** 첫 화면은 204개, 이름 축은 최대 176개라 다 받으면
페이지 하나가 1 MB 를 넘는다. 화면에 든 것만 받으면 처음 서른 개쯤이고, 그 뒤로는
`_headers` 의 하루 캐시에서 온다. 머리말의 국가 표시만 `eager` 다 — 거기는 처음부터
보이는 자리라 lazy 로 두면 늦게 뜬다.

**이름을 내용 해시로 두지 않았다**(`{cc}.svg` 고정). 글꼴과 다른 점이고, 그래서 캐시도
`immutable` 이 아니라 하루다 — 국기 도안이 실제로 바뀌는 일이 있다(2011 리비아 ·
2021 아프가니스탄).

**`alt` 는 빈 문자열이다.** 바로 옆에 나라 이름이 글자로 있어서, 국기를 다시 읽어
주면 같은 말을 두 번 듣는다.

**크기를 HTML 속성과 CSS 양쪽에 적는다.** 속성(`width="20" height="15"`)은 그림이 늦게
와도 줄이 밀리지 않게 자리를 미리 잡고, CSS 는 글자 크기에 흔들리지 않게 못박는다.
흰 바탕이 큰 국기(일본·나이지리아)는 밝은 종이색 위에서 경계가 사라지므로 잉크색을
아주 연하게 깐 테두리를 두른다.

### 두 벌을 들고 있는 유일한 자리

`public/shared/dday.js` 도 국기를 조립한다 — 선택기 204줄과 "오늘 쉬는 나라" 는
브라우저가 그리기 때문이다. 그 파일은 브라우저가 받는 것이라 `tools/flags.mjs` 를
import 할 수 없어서 경로와 크기를 두 벌 들고 있다.

그래서 `check-pages` 가 **dday.js 가 실제로 그린 국기를 HTML 쪽 모양과 글자 단위로
견준다.** 크기를 한쪽만 고치면 바로 걸린다(일부러 22px 로 바꿔 확인했다).

### 일부러 깨뜨려 본 것

국기 파일 지우기 · 나라 없는 국기 심기 · MIT 고지 지우기 · SVG 자리에 HTML 넣기 ·
이모지 국기 되살리기 · 국기와 링크를 다른 나라로 어긋내기(첫 화면·순위·이름 축 셋 다) ·
dday.js 쪽 크기만 바꾸기. 여덟 다 문다.

**그 과정에서 조용히 죽어 있던 검사를 하나 찾았다.** 선택기 정렬 검사가
`</span>([^<]+)<span class="cc">` 로 이름을 뽑았는데, 국기를 `<img>` 로 옮기면서 이름이
`<span class="cn">` 안으로 들어가 **아무것도 못 잡게 되었다.** 빈 배열은 늘 "정렬돼
있다" 로 통과하므로 검사는 조용히 초록이었다. 지금은 **뽑은 개수가 줄 수와 같은지
먼저 본다** — 무늬가 마크업과 어긋나는 순간 그 사실 자체가 실패가 된다.

## 황금연휴

주말과 공휴일이 이어져 사흘 이상 쉬는 구간을 국가마다 따로 싣는다. 같은 Nager 에
엔드포인트만 하나 더다 — `/LongWeekend/{year}/{cc}`. 주말이 어느 요일인지는 나라마다
다른데(이집트는 금·토) 그건 Nager 가 안다.

```json
{"s":"2026-05-01","e":"2026-05-05","b":["2026-05-04"]}
```

**일수를 담지 않는다.** `s` 와 `e` 에서 나온다. 담아 두면 자료 안에서 두 값이 갈라질 수
있고, 그러면 그것까지 검사해야 한다. `b` 는 징검다리 — 쉬는 날이 아닌데 하루 쓰면
앞뒤가 이어지는 날이다.

**우리가 담지 않은 공휴일에만 걸린 연휴는 버린다.** Nager 의 LongWeekend 는 `types` 를
가리지 않는데 우리 표에는 `Public` 만 있다. 그대로 실으면 표에 없는 날을 근거로
"5일 연휴" 라고 적는 페이지가 나온다 — 페이지 안에서 앞뒤가 맞지 않는다.
버린 건수는 생성기가 찍는다. 조용히 사라지면 다음 달에 왜 줄었는지 알 수 없다.

날짜 하나가 아니라 구간이라 D-day 의 갈림길이 셋이다.

| 지금 | 표의 표시 | 카드의 표시 |
| --- | --- | --- |
| 시작 전 | `D-12` | `D-12  5일 연휴` |
| 그 사이 | `연휴 중` | `연휴 중  5일 연휴` |
| 끝난 뒤 | `D+3` | (다음 연휴로 넘어간다) |

카드의 "다음 연휴" 는 **지금 붙어 있는 연휴가 있으면 그것이다.** 남은 이틀을 두고 두 달
뒤 연휴를 가리키면 카드가 거짓말을 한다. `dday.js` 의 `classifyBreaks()` 가 그 규칙을
한 군데에 담고, 국가 페이지 카드와 첫 화면 카드가 같은 함수를 쓴다.

## 이름 축 (`/holiday/`)

세 번째 축이다. 국가 축(204장)과 전세계 공통 축(`/sky/`) 다음으로 **공휴일 이름**이 왔다.

**밖에서 받아오는 것도, `data/` 에 더 만드는 파일도 없다.** 이미 담아서 검증하는
204개국 자료를 이름으로 묶기만 한다. `gen-pages.mjs` 가 그때그때 묶어 HTML 에 박고,
`check-pages.mjs` 는 **자기 손으로 다시 묶어** 그 HTML 과 견준다 — 묶는 코드를 나눠
쓰지 않으므로 둘이 같이 틀릴 수가 없다. `data/month/*.json` (파생물을 저장해 두고
견주는 쪽) 보다 검산점이 센 이유가 그것이다.

물음이 두 종류다. 어느 쪽도 국가 페이지로는 답이 나오지 않는다.

| | 이름 | 나라 | 날짜 |
| --- | --- | --- | --- |
| 같은 날 함께 쉰다 | 크리스마스 | 178개국 | 거의 하루 |
| 이름만 같고 날짜는 다 다르다 | 독립기념일 | 104개국 | 239가지 |

### 표기만 다른 것은 묶고, 낱말이 다른 것은 묶지 않는다

Nager 의 이름은 표기가 고르지 않다 — `All Saints' Day` · `All Saints Day` ·
`All Saints’ Day` 로 51개국이 세 갈래로 쪼개져 있었다. 그대로 세우면 같은 축일이
얇은 페이지 셋으로 갈려 서로 잡아먹는다. 그래서 소문자로 내리고 아포스트로피와
구두점을 떼고 공백을 하나로 줄인 꼴을 키로 삼아 **기계적으로** 묶는다.

**그 이상은 묶지 않는다.** `Labour Day` 와 `Workers' Day` 와 `May Day` 는 낱말이
다르므로 따로 남는다. 묶으면 노동절 하나로 160개국이 되지만 미국 Labor Day 는 9월이고
영국 May Day 는 노동절이 아니다 — **표기 정규화는 규칙이고, 뜻으로 묶는 것은 의견이다.**
의견은 어디서도 검사되지 않는다.

### 손으로 적는 것은 라벨뿐이다

`tools/holiday-names.mjs` 가 원화다. 여기 있는 것은 정규화한 이름 → `{ slug, ko, en }`
60쌍과 문턱(`MIN = 5`)뿐이고, **어느 나라가 언제 쉬는가는 한 줄도 손으로 적지 않는다.**

`docs/todo.md` 에서 국제 기념일을 내린 이유가 여기서는 걸리지 않는 까닭이다. 저쪽은
한국어 라벨이 166/554 였고 게다가 **사실 자체가 받아 적은 것**이라 검산점이 없었다.
여기서 라벨이 틀리면 화면에 보이고, 문턱을 새로 넘는 이름에 라벨이 없으면
`gen-pages` 가 종료 코드 1 로 멈춘다 — 그냥 두면 한국어 페이지에 영어 이름이 박힌다.

**장수는 자료가 정한다.** 그래서 슬러그를 `EXTRA` 에 손으로 적지 않고 `config.mjs` 의
`NAME_PAGE` 로 모양만 걸어 둔다. 뿌리(`holiday`)만 `EXTRA` 에 있으면 청소가 하위까지
통째로 지운다.

### 나라 칩은 카드로 새어 나가면 안 된다

이름 칸 안에 그날 쉬는 나라가 다 들어간다 — 크리스마스는 176개국이다. 그 칸을 그대로
카드에 옮기면 "다음" 한 줄에 176개 나라 이름이 쏟아진다. 그래서 칩을
`<span class="ccs">` 로 싸고 `dday.js` 의 `nameOf()` 와 `harness.mjs` 의 `parseRows` 가
그것을 떼어 낸다. 카드에 남는 것은 앞머리의 "176개국" 이다. 세 곳이 짝이므로 한 곳만
고치면 조용히 어긋난다.

### 세계가 함께 쉬는 날

허브(`/holiday/`)는 이름으로 보내는 자리이면서 같은 자료를 **날짜 축**으로 뒤집은 표를
하나 이고 있다. 첫 화면의 "오늘 어느 나라가 쉬나" 는 있는데 "어떤 날에 가장 많은
나라가 쉬나" 는 여태 아무 데도 없었다 — 이름이 아니라 날짜로 세면 나온다.
2026년에 10개국 이상이 함께 쉬는 날 44일이고, 새해 197개국 · 크리스마스 178 ·
노동절 159 · 부활절 월요일 120 순이다.

**허브 표에는 나라 칩을 두지 않는다.** 44일 × 최대 197개국이면 페이지가 죽는다.
수와 대표 이름만 적고 나라는 이름 낱장이 맡는다. `check-pages` 가 허브에 칩이
들어오면 문다.

## 나라끼리 견주기 (`/rank/`)

한 장이다. 표가 넷 — 최장 연휴 · 공휴일이 많은 나라 · 적은 나라 · 연휴가 많은 나라.
전부 표지 연도 상위 20줄이고, 이것도 자료를 하나도 더 만들지 않는다.

**세는 단위가 국가 페이지와 다르고, 그걸 각주로 밝힌다.** 국가 페이지의 요약은 자료
**건수**를 센다 — 대한민국 2025-05-05 은 어린이날과 부처님 오신 날이 겹쳐 두 건이다.
순위에서 그렇게 세면 "쉬는 날" 이 부풀려지므로 여기서는 **날짜 수**를 세고 열 이름을
"쉬는 날짜" 로 두었다. 같은 사이트에서 같은 것을 다르게 세는 것은 숨기지 말고 적는다.

**최장 연휴 표는 `tr data-s`/`data-e` 를 그대로 쓴다.** 국가 페이지의 연휴 표와 같은
`classifyBreaks()` 가 D-day 를 붙인다 — 여기서 규칙을 새로 만들면 사이트 안에서
D-day 가 두 가지 뜻을 갖는다.

**"주말에 겹쳐 날아간 공휴일" 은 한 번 뺐다가 되살렸다.** 처음 재 보니 2026년
(국가, 날짜) 2,500쌍 중 540(21.6%)이었는데, 그건 **토·일 고정으로 센 값이라**
이집트(금·토)에서 조용히 틀린다. 주말이 어느 요일인지가 우리 자료에 없어서 뺐다.

**그 자료가 `Intl` 에 있었다.** `new Intl.Locale('und-EG').getWeekInfo().weekend` 가
`[5, 6]` 을 준다 — 204개국 전부 잡히고 파일도 네트워크도 늘지 않는다. 그래서
요일 축(`/weekday/`)에서 되살렸고, **나라별 주말로 세니 540 이 아니라 544(21.8%)** 다.
네 건이 그 차이인데, 그게 바로 "조용히 틀린다" 던 그 몫이다.

주말이 토·일인 나라가 195개국, **금·토가 8개국, 일요일 하루뿐인 나라가 1개국**(인도)이다.
`check-pages` 는 전 세계 합계가 **토·일 칸의 합과 같으면 실패**로 본다 — 같아지는
순간 나라별 주말을 안 보고 있다는 뜻이다.

## 절기와 삭망과 음력 (`/sky/`)

국가 축이 아닌 첫 페이지였다. 절기도 삭망도 유성우도 **온 세계가 같은 순간을 공유**하므로
204개국으로 쪼갤 것이 없다 — `data/sky.json` 한 벌(23KB)이 전부다.
그래서 `config.mjs` 에 `EXTRA` 가 생겼다. 그전까지는 "첫 화면 아니면 전부 국가 페이지"
였고, `check-pages` 가 그 가정 위에 서 있었다.

### 밖에서 받아오지 않는다

`tools/astro.mjs` 가 직접 계산한다. Nager 도, 다른 API 도 안 탄다.

- **절기** — 태양의 겉보기 황경이 15°의 배수가 되는 순간. 24개가 한 식에서 나오고
  분점·지점은 그중 넷이다(0° · 90° · 180° · 270°).
- **삭망** — Meeus 제49장.
- **유성우** — **날짜를 손으로 적지 않는다.** 국제유성기구가 극대기를 태양 황경으로
  정의하므로, 위의 태양 계산에 그 황경을 넣으면 해마다 맞는 날짜가 나온다.
  해가 바뀌어도 표를 고칠 일이 없다.
- **음력** — 위의 삭과 중기 둘로 나온다. 새 이론이 없다.

### 음력은 시간대가 자료의 일부다

절기도 삭망도 유성우도 온 세계가 같은 순간을 공유하고, 갈리는 것은 날짜뿐이다 —
그래서 `sky.json` 이 kst·utc 두 칸을 담는다. **음력은 다르다.** 초하루가
*"삭이 든 날"* 이므로 기준 시간대를 고르지 않으면 달력이 아예 성립하지 않는다.

한국 음력이라 KST 한 벌만 담고, **en 페이지도 같은 표를 본다.** 그래서 이 갈래만
`note`·`foot` 를 따로 갖는다 — 다른 갈래의 "이 페이지는 UTC 기준" 을 그대로 쓰면
영어 페이지가 거짓말을 한다.

그 결과가 실제로 눈에 보이는 해가 있다. **2027년 설날은 한국 2월 7일, 중국 2월 6일이다**
— 삭이 2027-02-06 15:56 UTC 라 중국(UTC+8)에서는 2월 6일 23:56 이고 한국에서는 2월 7일
00:56 이다. 이건 오차가 아니라 사실이고, 맞추려 들면 달력을 틀리게 만든다.

규칙은 셋이다 (한국천문연구원·중국 농력이 함께 쓰는 것).

1. 음력 달의 첫날은 **삭이 든 날**
2. **동지는 언제나 11월에** 든다
3. 두 동지월 사이에 달이 13개 들면 윤달이 있고, 윤달은 **중기가 하나도 들지 않는
   첫 달**이다 (무중치윤법). 중기는 태양 황경이 30°의 배수가 되는 순간 — 24절기의 절반이다

셋을 다 검사에 걸면 달력이 온전히 정해진다. 삭과 중기는 이미 분 단위로 검증돼
있으므로(아래 공표값 12건) 남는 것은 "번호를 어떻게 붙였나" 뿐이고, 그게 이 셋이다.
그 위에 Nager 공휴일로 밖에서 한 번 더 본다 — 추석(음력 8월 15일)과 홍콩
中秋節翌日(8월 16일)은 3년 다 정확히 맞고, 설날은 연휴 구간 안에 들고(Nager 가
일요일에 걸린 날을 빼고 주는 나라가 있다), 중국 春节 은 위의 이유로 하루까지 허용한다.

### 태양은 왜 VSOP87 인가

처음에는 Meeus 저정밀식(0.01°)으로 짰다. **2025년 동지가 KST 자정 정각에 떨어졌다.**
오차 한계가 ±15분이니 12월 21일인지 22일인지 정할 수 없었다 — 동지 날짜가 틀린 절기
페이지는 안 내는 게 낫다.

그래서 VSOP87D 정본(CDS 카탈로그 VI/81)을 받아 `|A|·0.03^p ≥ 1e-7` 로 절단했다.
2425항 중 172항이 남고 오차는 **11분 → 1분**이 되었다. 지금 동지의 여유는 2분이다.

계수를 기억으로 적지 않고 `tools/gen-vsop87.mjs` 로 받아 만든다. 172줄짜리 숫자
뭉치는 손으로 검산할 수 없으니, 어디서 왔고 무엇을 버렸는지 코드로 남겨 둔다.

### 날짜는 시간대마다 갈린다

순간은 하나인데 날짜는 아니다. 2025년 동지는 UTC 12월 21일 15:02, 한국은 12월 22일
00:02 다. **ko 페이지는 KST, en 페이지는 UTC** 로 굳혀 박고 각주로 밝힌다.

굳히는 일은 `gen-sky.mjs` 한 군데에서만 한다. 브라우저가 다시 계산하면 HTML 에 박힌
날짜와 갈라질 수 있어서, `sky.json` 이 두 기준 시간대의 날짜·시각을 함께 담는다.

### 그림은 자료에서 나온다

절기·삭·보름·유성우 표에 16×16 SVG 를 하나씩 단다(`public/sky-icons/`). 국기와 같은
자리 — 우리 오리진, `<img>`, `loading="lazy"` — 지만 **받아 온 것이 아니라
`tools/sky-art.mjs` 가 그린 것**이라 고지가 없고 판을 박을 것도 없다.

72줄짜리 표에 똑같은 그림을 72번 찍으면 그건 장식이지 정보가 아니다. 그래서 그림을
자료에서 뽑는다.

| 갈래 | 그림 | 무엇이 다른가 |
| --- | --- | --- |
| 절기 | 원 위의 해 24개 | 태양의 황경이 곧 `k`(=황경/15)다. 표를 내려가면 해가 원을 한 바퀴 돈다 |
| 삭·보름 | 빈 원 · 찬 달 | 달이 안 보이는 날과 다 보이는 날 그대로 |
| 유성우 | 빗줄기 2·3·5개 | ZHR 100 이상 다섯, 25 이상 셋, 나머지 둘 |

**분점 둘과 지점 둘은 정확히 동서남북에 선다** — `k=0·6·12·18` 이 각각 오른쪽·위·
왼쪽·아래다. 시작 각도나 회전 방향을 뒤집으면 그림은 여전히 그럴듯한데 하지가 아래로
가므로, 검산이 네 자리를 못박아 둔다.

**음력에는 안 단다.** 초하루가 곧 삭이라 삭 그림을 그대로 쓸 수 있지만, 그러면 같은
그림이 두 갈래에서 다른 뜻으로 읽힌다 — 저쪽 표의 한 행은 순간이 아니라 달이다.
그래서 음력 표는 그림 칸을 통째로 뺀다(머리도 세 칸이다).

**유성우는 비처럼 긋는다.** 처음에는 굵은 줄기 한둘이었는데 유성우로 안 읽혔다 —
유성우는 한 줄기가 아니라 쏟아지는 것이다. 다섯 줄기가 모두 기울기 -1 이고 `x+y` 로
2.47px 씩 벌어져 밭을 이룬다. 세기가 오를수록 밭이 가운데에서 바깥으로 자란다.

**색이 둘인 이유.** `<img>` 로 실으면 바깥 CSS 가 닿지 않는다 — `currentColor` 도
`base.css` 의 토큰도 그림 안으로 못 들어간다. 그래서 색을 그림 안에 적는다.

*잉크*(`#78849a`, 밝은 쪽 `--ink-3`)는 테마를 묻지 않는 값 하나다. 흰 종이에서 3.6:1,
어두운 종이에서 5.1:1 이라 그림에 필요한 3:1 을 양쪽에서 넘는다.

*달빛*(`#b8860b` / 어두운 종이 `#e8bf4a`)은 보름달과 유성우의 밝은 줄기에만 쓴다.
회색 보름달이 달로 안 보인다는 판단이었다. **노랑은 잉크와 달리 한 값으로 두 종이를
못 덮는다** — 흰 종이에서 읽히려면 어두워야 하고 그러면 어두운 종이에서 묻힌다.
그래서 이것만 SVG 안에 `prefers-color-scheme` 를 적는다. 미디어 질의가 안 먹는
브라우저는 기본값(밝은 쪽)을 쓰는데 그 값이 어두운 종이에서도 5.6:1 이라, 최악이
"덜 밝은 금색" 이지 안 보이는 것이 아니다.

`--today`(라즈베리)도 `--local`(지역 한정)도 아닌 새 값이다. 뜻이 다른 색을 값만 빌려
쓰면 어느 날 저쪽을 옮길 때 달이 같이 따라간다. 삭은 잉크 그대로다 — **안 보이는 달**이라
빛날 자리가 없고, 둘을 같은 색으로 두면 "찼나 비었나" 위에 "빛나나" 가 겹친다.

**그린 것을 다시 읽어서 본다.** 좌표를 계산한 그 식으로 되짚으면 식이 틀렸을 때 검사도
같이 틀린다. `validate()` 는 문자열이 된 SVG 에서 숫자를 도로 뽑아 — 상자를 넘지 않나 ·
스물넷이 서로 다른 자리에 서 있나 · 분점·지점이 동서남북인가 · 삭과 보름이 다르게
생겼나 · 빗줄기가 서로 겹치지 않나 · 달빛 클래스와 그 `<style>` 이 짝인가 — 를 본다.

겹침 검사는 **실제로 걸렸다.** 처음 앉힌 유성우 줄기 둘이 같은 선(`x+y=16`) 위에
있어서, 짧은 줄기가 아니라 첫째가 길게 이어진 것으로 보이고 그 중간에 머리 점이 하나
박혔다. 다섯 다 기울기가 -1 이라 `x+y` 가 곧 그 선의 이름이고, 그 차이를 √2 로 나누면
두 줄기 사이 거리가 나온다.

달빛 쪽에도 조용한 자리가 하나 있다. 채움과 선을 **한 클래스에 같이 적으면**
`<circle>` 이 stroke 를 받는데 `stroke-width` 의 기본값이 1 이라 원이 반지름 0.5 만큼
커진다 — 상자 검사는 `stroke-width` *속성*만 보므로 그걸 못 잡는다. 그래서 `.gf`(채움)와
`.gs`(선)를 갈라 두고, 원이 선 클래스를 물지 않았는지 따로 본다.

### 그림 하나가 줄의 밑선을 바꿨다

첫 화면 목록에 그림을 넣자 오른쪽 칸이 몇 픽셀 내려앉았다 — "다음 절기" 와
"D-3 백로" 가 어긋나 보였다. 범인은 `.worldwide .who` 의 `display:inline-flex` 다.

줄(`li`)이 `align-items:baseline` 인데, **플렉스 상자의 밑선은 첫 항목에서 나온다.**
첫 항목이 그림이면 밑선이 없으므로 그림의 아래 모서리가 대신 쓰인다. 그러면 이 칸의
글자는 제 밑선대로 앉아 있는데 줄은 그림 밑을 밑선으로 알고 옆 칸을 그만큼 내린다.
그림이 없던 시절에는 첫 항목이 글자라 아무 일도 없었고, 국기가 들어왔을 때는
`align-items:center` 가 그 어긋남을 눈에 안 띌 만큼만 만들고 있었다.

고친 방법은 플렉스를 걷어내는 것이다. 그냥 글자 줄로 두면 밑선이 원래대로 글자에서
나오고, 그림은 제 `vertical-align` 이 자리를 잡는다 — 국기 -2px · 하늘 아이콘 -4px 로
사이트 어디서나 쓰는 그 값이다. 되돌리기 쉬운 자리라 `check-pages` 의 CSS 계약에
**있으면 안 되는 것**으로 박아 두었다(있어야 하는 것만 보던 목록에 처음 생긴 항목이다).

### 여기도 두 벌을 들고 있다

국기와 같다. 첫 화면의 "다가오는 절기와 삭망" 은 `dday.js` 가 그리는데 그 파일은
브라우저가 받는 것이라 `tools/sky-art.mjs` 를 import 할 수 없다. 그래서 이름 짓는
규칙(황경 `k` · 삭/보름 · ZHR 층)과 `<img>` 모양을 두 벌 들고 있다.

`check-pages` 가 **스물아홉 가지 모두에 대해 두 벌을 견준다.** ZHR 층은 경계를 걸치는
수(150·100·99·25·24·0)로 본다 — 가운데 값만 넣으면 문턱이 한 칸 옮겨져도 두 벌이
여전히 같은 답을 내서 조용히 통과한다.

### 일부러 깨뜨려 본 것

그림 파일 내용 어긋내기 · 원화만 고치고 `gen-sky-icons` 안 돌리기 · 행에서 그림 칸
빼기 · 삭 자리에 보름 그림 심기 · 음력 표에 그림 심기 · `dday.js` 쪽 크기만 바꾸기 ·
`dday.js` 쪽 ZHR 문턱만 옮기기 · `k` 자리수 규칙 어긋내기 · CSS 규칙 지우기 ·
궤도를 키워 해가 상자를 넘게 하기 · 회전 방향 뒤집기 · 스물넷을 한 자리에 몰기 ·
유성우 줄기 겹치기 · 원에 선 클래스 물리기 · `<style>` 블록 빼기 · 어두운 종이용 달빛
빼기 · `.worldwide .who` 를 다시 플렉스로 되돌리기. 열일곱 다 문다.

## 오늘 공휴일인 나라

첫 화면에 "오늘 어느 나라가 쉬는가" 를 띄운다. 국가별 파일로는 답할 수 없는 물음이라
(204개를 다 받아야 한다) `gen-holidays.mjs` 가 같은 자료를 날짜로 한 번 더 색인해
`data/month/YYYY-MM.json` 을 만든다.

달 단위로 쪼갠 이유 — 하루 단위면 파일이 973개가 되고, 한 파일이면 900KB 를 받아
그중 하루치만 쓴다. 달 파일은 36개에 9~16KB 라 브라우저가 이번 달 하나만 받는다.

같은 자료를 두 벌 들고 있으니 갈라질 수 있다. `check-pages.mjs` 가 국가별 파일과
달 색인을 (날짜, 국가, 이름) 으로 통째로 견주고, 한 건이라도 어긋나면 배포를 막는다.

## 요일 축 (`/weekday/`)

`/rank/` 과 같은 축의 **둘째 장**이다. 축 탭을 다섯으로 늘리지 않았다 — 물음이
"나라끼리 견주기" 와 같은 것이라 그 축을 잡고, `/sky/term/` 이나
`/holiday/{이름}/` 이 쓰는 관례를 그대로 따른다. 순위 페이지 끝에서 들어간다.

**자료를 하나도 더 만들지 않는다.** 이미 담아 검증하는 204개국 공휴일을 **요일**로
다시 묶은 것이 전부다 — 이름 축과 같은 방식이고, `data/` 에 파일이 늘지 않는다.

### 요일은 균등하지 않다 — 3.8배

2026년 204개국의 쉬는 날짜 2,500건을 요일로 세면 이렇다.

| 요일 | 건수 | 비율 | 고른 분포 대비 |
| --- | --- | --- | --- |
| 금 | **617** | 24.7% | 1.73배 |
| 월 | 520 | 20.8% | 1.46배 |
| 목 | 451 | 18.0% | 1.26배 |
| 토 | 288 | 11.5% | 0.81배 |
| 일 | 252 | 10.1% | 0.71배 |
| 화 | 211 | 8.4% | 0.59배 |
| 수 | **161** | 6.4% | 0.45배 |

고르게 흩어진다면 각각 14.3%다. 실제로는 6.4%에서 24.7%까지 흩어지고 **금요일이
수요일의 3.8배**다.

### 쏠림의 정체는 대체공휴일이 아니라 고정 날짜다

처음에는 부활절 계열(성금요일=금 · 부활절 월요일=월)이 원인이라고 봤는데,
자료를 세어 보니 아니었다.

- **2026-01-01 은 목요일이고 그 하루가 197개국의 공휴일이다** — 목요일 451건의 43.7%
- **2026-12-25 는 금요일이고 178개국이다** — 금요일 617건의 28.8%

고정 날짜 하나가 200개국에서 **같은 요일에** 떨어진다. 그게 쏠림의 절반이다.
부활절 계열은 그 위에 얹힌다(성금요일 128 · 부활절 월요일 126 · 성령강림절 월요일 51 ·
승천일 51).

### 이름이 걸치는 요일 수가 그 이름의 성질이다

이름 축의 정규화(`NORM`)와 원화(`NAMES`)를 그대로 써서, 이름마다 그 해에 몇 요일에
떨어지는지 센다. **여기서 묶는 규칙을 새로 만들면 두 축이 다른 이름 집합을 갖는다.**

- **1개 요일** — 요일이 정의에 박혀 있다. 성금요일 128건은 전부 금요일이다
- **7개 요일** — 나라마다 날짜가 다르다. 독립기념일 106건이 그렇다
- 그 사이 — 대체공휴일이나 달력 변형. 새해가 2개 요일, 크리스마스가 5개 요일이다

### 주말 겹침은 해마다 두 배로 흔들린다

| 해 | 쉬는 날짜 | 주말 겹침 | 비율 | 1/1 | 12/25 |
| --- | --- | --- | --- | --- | --- |
| 2025 | 2,499 | 415 | **16.6%** | 수 | 목 |
| 2026 | 2,500 | 544 | **21.8%** | 목 | 금 |
| 2027 | 2,487 | 783 | **31.5%** | 금 | 토 |

고정 날짜는 해마다 요일이 하루씩 밀린다. 그래서 2027년에는 크리스마스가 토요일이고,
**160개국이 같은 해에 함께 손해를 본다.** 균등 기대치(28.6%)를 넘는 해다.
이 손해는 나라별로 흩어지지 않고 전 세계가 동시에 겪는다 — 그게 이 표의 요점이다.

### 검산점은 이름 축과 같은 것이다

`check-pages` 가 **자기 손으로 다시 세어** HTML 과 견준다(`WK_REF`). `weekdayIndex` 를
import 하지 않는 것이 요점이고, 그래서 둘이 같이 틀릴 수 없다.

내부 검산도 셋 걸어 두었다.

- **요일 일곱 칸의 합 = 그 나라의 쉬는 날짜 수** — 나라마다, 해마다
- **세는 단위가 순위 페이지와 같은가**(날짜 수). 건수로 바꿔 보면 40건이 실패한다
- **전 세계 주말 겹침이 토·일 칸의 합과 다른가** — 같아지면 나라별 주말을 안 보는 것이다

일부러 깨뜨려 본 것 — 요일 한 칸의 수 바꾸기 · 표의 한 줄을 다른 나라로 바꾸기 ·
세는 단위를 건수로 바꾸기 · 표 스타일 지우기. 넷 다 문다.

## 두 언어

경로가 곧 언어다 — `/kr/` 은 한국어, `/en/kr/` 은 영어. 페이지마다 canonical(자기 주소)과
hreflang 세 줄(ko · en · x-default→en)이 **양쪽에 똑같이** 들어간다. 한쪽만 있으면
구글은 그 hreflang 을 통째로 버리므로, 짝이 없으면 `gen-sitemap.mjs` 가 멈춘다.

말은 두 군데에 있다.

- **페이지 문안** — `tools/gen-pages.mjs` 의 `L.ko` / `L.en` 표
- **화면에서 바뀌는 문안** — `public/shared/dday.js` 의 `STR.ko` / `STR.en` 표

`dday.js` 는 한 파일로 두 언어를 다 쓴다. 갈림길은 `<html lang>` 하나뿐이라
한쪽만 고쳐지는 일이 없다. 자료(`data/*.json`)도 한 벌이고, 국가 이름은 한글·영어를
같이 담아 두었다 — 그래서 영어 화면에서도 "대한" 으로 검색된다.

국가 목록 정렬은 **보이는 이름** 기준이다. `countries.json` 은 한글 이름순으로
저장돼 있어서, 영어 화면에서 그대로 쓰면 Ghana(가나)가 맨 앞에 오는 무작위 순서가 된다.

## 글꼴

머리에 남의 오리진이 셋 있었다 — `fonts.googleapis.com` · `fonts.gstatic.com` ·
`cdn.jsdelivr.net`. `public/` 을 Cloudflare 에 그대로 얹는 사이트인데 DNS+TLS
핸드셰이크를 세 번 더 했고, 그중 둘은 첫 페인트를 막는 CSS 였다. 지금은 조각을 받아
`public/fonts/` 에 커밋해 둔다 — 같은 오리진 · 같은 연결 · 같은 CDN 캐시고,
이 디렉터리의 "의존성 없음" 원칙에도 맞는다.

| | 전 | 후 |
|---|---|---|
| 렌더 경로의 오리진 | 3 | **0** |
| 렌더를 막는 외부 CSS | 2 | 0 |
| 글꼴 CSS (gzip) | 145 KB | **8.4 KB** |
| 한 페이지가 받는 글꼴 | (같음) | 258 ~ 414 KB |

**조각을 다 받지는 않는다.** dynamic subset 은 `unicode-range` 로 갈려 있어서 사이트가
쓰지 않는 글자의 조각은 아무도 내려받지 않는다 — 커밋해 봐야 저장소만 무겁다.
`public/` 을 통째로 훑어(HTML·JSON·JS·CSS) 쓰는 글자 1,182자를 모으고 걸리는 것만 남긴다.
upstream 1,030면 → **92면 · 1,157 KB**.

가지치기의 위험은 하나뿐이다. 나라가 하나 늘어 새 한글 음절이 들어오면 그 글자만
대체 글꼴로 나오는데, **화면으로도 잘 안 보인다.** 그래서 버린 조각의
`unicode-range` 를 `tools/fonts-lock.json` 에 적어 두고 `check-pages` 가 그 기록으로
"버린 조각이 이제 필요해졌다" 를 잡는다.

**가변본을 먼저 붙였다가 물렸다.** `base.css` 의 `--sans` 첫 자리가
`'Pretendard Variable'` 이라 가변 dynamic-subset 을 실었는데, 조각 하나가 25.4 KB 로
정적본 10.5 KB 의 **2.4배**다 — 무게 축을 통째로 이고 다닌다. `--sans` 가 실제로
쓰는 무게는 400 과 500 둘뿐이라(700 은 serif 쪽이다) 정적 두 벌이 저장소에서도
방문자 쪽에서도 이긴다. 그러면서 드러난 것: **첫 자리에 적힌 이름을 우리가 나른 적이
없었다.** 그 글꼴을 이미 깔아 둔 사람만 다르게 보였고 아무 데서도 티가 안 났다.
지금은 `check-pages` 가 `base.css` 를 진짜로 놓고 `fonts.css` 와 견준다.

파일 이름에 내용 해시가 박혀 있다(`pretendard.278.62feb389.woff2`). `_headers` 의
`immutable` 이 참말이 되고, 덤으로 검사가 네트워크 없이 무결성을 본다.

**고르기지 자르기가 아니다 — 그 선을 넘지 말 것.** 483자밖에 안 쓰는데 92면 1 MB 를
이고 있으니 직접 서브셋을 떠서 줄이고 싶어지지만, 셋 다 SIL OFL 1.1 이고 OFL 은
**고친 것을 배포하려면 Reserved Font Name 을 떼고 이름을 바꾸라**고 한다. Pretendard 에는
RFN 이 걸려 있어서, 글리프를 직접 잘라 내는 순간 `font-family:'Pretendard'` 라고 쓸 수
없다. 그래서 upstream 이 이미 잘라 배포하는 조각을 **받은 바이트 그대로** 골라 담기만
한다. 파일 이름은 해시를 붙여 바꾸지만 RFN 이 거는 것은 폰트 안의 이름이지 파일
이름이 아니다. 고지와 라이선스 전문은 `/fonts/LICENSE.txt` 로 같이 실어 나른다 —
`check-pages` 가 이 파일이 없어지면 문다.

**preload 는 넣지 않았다.** 어느 조각이 필요한지가 페이지마다 다르다 — 한 벌을 골라
418개 머리에 박으면 맞는 페이지에서는 1 RTT 를 벌지만 틀린 페이지에서는 아무도 안 쓰는
파일을 통째로 받는다. 페이지마다 계산해 박으면 `gen-pages` 가 `gen-fonts` 의 출력을
읽고 `gen-fonts` 는 페이지의 글자를 읽어, 생성기 둘이 서로를 물어 처음 한 번을 못 돌린다.

`gen-fonts.mjs` 는 `gen-holidays.mjs` 처럼 **손으로 돌리는 네트워크 단계**고 Cloudflare
빌드에는 없다. 빌드가 돌리는 것은 `check-pages.mjs` 뿐이고 그건 네트워크를 타지 않는다.
`node tools/gen-fonts.mjs --check` 는 upstream 이 판을 올렸는지만 본다.

## 검사

`tools/check-pages.mjs` 가 546개 페이지를 브라우저 없이 돌려 본다.
jsdom 을 쓰지 않는다 — `node:vm` + 최소 DOM·fetch 스텁이면 충분하고, 의존성이 늘지 않는다.

보는 것:

1. 페이지가 예외 없이 구동되고 `window.DDAY` 손잡이가 나오나
2. `dday.js` 가 찾는 `#picker` · `#now` · `#next` · `#prev` · `#break` 가 HTML 에 있나
3. 주요 태그가 짝이 맞나
4. canonical(자기 주소) · hreflang 3줄 · title · description · 파비콘 4줄 · 자산 링크
   (파비콘은 파일을 열어 정사각 + 48 의 배수인지 본다 — 구글 검색결과 아이콘 조건)
5. HTML 표의 날짜 집합이 `data/<CC>.json` 과 같나, `data/month/*.json` 이
   국가별 파일과 한 건도 어긋나지 않나
6. 황금연휴가 스스로 앞뒤가 맞나 — 사흘 이상인가, 우리가 담은 공휴일에 걸려 있나,
   징검다리가 구간 안의 공휴일 아닌 날인가, 시작일순이고 겹치지 않나. 그리고 연휴 표가
   그 자료와 같나, 연휴가 0건인 국가에는 카드 줄도 섹션도 없나
6.5. **천문 검산점** — 절기·삭망은 우리가 직접 계산한 것이라 "받은 대로 찍혔나" 로는
   아무것도 검사되지 않는다. 두 번째 점을 저장소 안에서 찾는다. 일본은 `春分の日`·
   `秋分の日` 를 실제 천문 분점(일본 표준시)으로 정하고, 음력 1월 1일은 삭이 있는 날,
   음력 8월 15일은 그 14일 뒤다. Nager 에서 온 공휴일 자료와 **21개 지점**을 견준다.
   이름이 바뀌어 검산점이 통째로 사라지는 것이 가장 나쁘므로 최소 개수를 박아 두었다.
   그것과 별개로 `sky-fixture.mjs` 의 분점·지점 공표 시각 12건과 **분 단위로** 견준다 —
   공휴일 쪽 검산점은 날짜만 주므로 1분 오차와 70분 오차를 가르지 못한다
7. 고정 날짜(`2026-06-15`)를 넣고 `classify()` 가 낸 다음/지난/오늘이
   검사기가 따로 계산한 값과 같나. 이어서 실제로 그려진 오늘 카드 문안,
   "오늘 공휴일인 나라" 목록(나라 수·이름·공휴일 이름·정렬), 그리고 dday.js 가
   채운 선택기 204줄의 정렬까지 견준다.
   연휴는 갈림길이 셋(전·중·후)이라 `classifyBreaks()` 도 같은 고정 날짜로 견준다 —
   연휴가 4천 건이라 그 날짜 하나로 셋이 다 지나간다
8. `countries.json` · 페이지 디렉터리 · 양쪽 첫 화면 링크가 1:1 인가,
   목록이 보이는 이름순인가
9. `sitemap.xml` 의 URL 집합이 페이지 집합과 같고 hreflang 이 url 마다 세 줄인가
10. 브라우저 지역 감지가 기대대로 갈리나 (`ko-KR`→KR, `en-US`→US, `ko`→KR, 모르는 지역→null),
   그리고 `localStorage` 에 무엇이 담겨 있든 그 감지를 바꾸지 못하나
11. ko / en 이 짝으로 있고 수가 같나
12. 영어 페이지에 한국어가 남아 있지 않나 (공휴일 이름처럼 자료에서 오는 자리는 뺀다)
13. 어느 페이지도 `localStorage` 에 아무것도 남기지 않나
14. 푸터 연락처가 제대로 조립되나 — 조각이 하나 있고, `contact.js` 를 싣고,
    합친 결과가 기대한 주소이고, **완성된 주소가 소스 어디에도 없나**
15. `robots.txt` 의 Sitemap 줄이 `BASE` 와 같나, CSS 계약(스크롤 목록·오늘 강조·
    어두운 테마·좁은 화면)이 살아 있나, 404 가 언어 칸마다 있고 noindex 인가
16. **이름 축** — 문턱을 넘는 이름과 페이지가 1:1 인가, 표의 (날짜, 국가)가 국가별
    파일에서 **검사기가 직접 다시 묶은 것**과 같나, 칩 앞에 적힌 수가 실제 칩 개수와
    같나, 칩이 보이는 이름순인가, 허브가 이름 전부로 링크하며 국가 수까지 맞나,
    허브의 「함께 쉬는 날」 표가 날짜 축으로 다시 센 값과 같나
17. **순위** — 네 표의 순서·국가·값이 국가별 파일에서 다시 센 값과 같나, 각주에 적힌
    국가 수가 자료와 같나
17.5. **요일 축** — 요일 일곱 칸·주말 종류·해별·이름별 네 표와 국가 표 셋이,
    검사기가 **자기 손으로 다시 센 값**과 같나. 일곱 칸의 합이 날짜 수와 맞나,
    세는 단위가 순위 페이지와 같나(건수로 세면 갈라진다), 전 세계 주말 겹침이
    토·일 칸의 합과 **다른가**(같으면 나라별 주말을 안 보는 것이다)
18. **음력** — 초하루마다 삭이 있나, 동지가 든 달이 11월인가, 윤달에 중기가 없고
    다른 달에는 하나씩 있나, 한 음력 해의 평달 번호가 1..12 가 한 번씩인가,
    그리고 설날·추석·中秋節 18개 지점과 견준다
19. **축 탭** — 페이지마다 넷이 있고, 잡힌 것이 하나이고, 그 하나가 이 페이지의
    축이고, `aria-current="page"` 가 붙어 있고, 네 링크가 같은 언어 칸인가
20. **국기** — 나라와 1:1 인가(빠진 것·유령 둘 다), 내용이 정말 SVG 인가,
    MIT 고지가 있나, 이모지 국기가 남아 있지 않나, 그리고 **국기가 그 줄의 나라와
    같은가** (첫 화면·순위·이름 축 셋 다). dday.js 가 그린 국기가 HTML 쪽과
    같은 모양인지도 본다 — 경로와 크기를 두 벌 들고 있는 유일한 자리다
20.5. **하늘 아이콘** — 원화 자체가 성립하나(상자를 넘지 않나 · 스물넷이 서로 다른
    자리인가 · 분점·지점이 동서남북인가 · 빗줄기가 겹치지 않나 · 달빛 클래스와 그
    `<style>` 이 짝이고 원이 선 클래스를 물지 않았나), 파일이 원화와 1:1 이고
    내용이 같나(원화만 고치고 `gen-sky-icons` 를 안 돌린 자리를 막는다), 그리고
    **그림이 그 행의 자료와 같은가** — 절기는 황경 `k`, 삭·보름은 참·빔, 유성우는
    ZHR 층이다. 음력 표에는 그림도 그림 칸도 없어야 한다. dday.js 가 그린 그림이
    HTML 쪽과 같은 모양인지 스물아홉 가지 모두 견준다
21. **글꼴** — 렌더 경로(stylesheet·script·preload)에 남의 오리진이 다시 들어오지
    않았나, 페이지가 `/fonts/fonts.css` 를 걸고 있나, `fonts.css` 가 가리키는 파일이
    다 있고 이름의 해시가 내용과 맞나, 92면 전부에 `font-display:swap` 이 있나,
    `base.css` 가 첫 자리에 부르는 글꼴 셋을 우리가 실제로 나르나, 그리고
    **버린 조각이 이제 필요해지지 않았나**

## 홈은 늘 내 지역

첫 화면의 "내 국가" 카드는 **브라우저 지역 설정만** 본다 (`Intl.Locale(...).maximize().region`).

한때 고른 국가를 `localStorage` 에 기억하고 그걸 먼저 썼는데, 국가 페이지를 **열어 본
것만으로도** 기억되는 바람에 이라크 공휴일을 한 번 구경하면 홈이 계속 이라크가 되었다.
지금은 사이트 전체가 `localStorage` 를 쓰지 않고, 검사가 읽는 쪽과 쓰는 쪽을 모두 막는다 —
값을 심어 두고 감지가 흔들리는지 보고, 어느 페이지도 무엇을 남기지 않는지 본다.

## 연락처

푸터의 메일 주소는 HTML 어디에도 완성된 형태로 없다. 로컬 파트와 도메인을 뒤집어
따로 담아 두고 `shared/contact.js` 가 합친다 — `@` 는 소스에 아예 등장하지 않는다.
backend-internals 와 같은 방식이고 같은 파일을 쓴다.

정규식으로 훑는 수집기는 아무것도 못 가져가고, 헤드리스 브라우저로 렌더링까지 하는
수집기는 그대로 가져간다. 그건 이 방식으로 못 막는다.

검사가 조립 결과까지 본다. 조각 한 글자가 틀리면 조용히 엉뚱한 주소가 나오는데,
`data-d` 를 `moc.02noilimrev` 로 바꿔 보면 잡힌다.

## 알려진 제약

- **D-day 는 보는 사람의 기기 날짜로 계산한다.** 다른 시간대의 국가를 볼 때는 하루
  어긋날 수 있다. 국가별 대표 시간대를 담으면 고칠 수 있지만, 그러려면 CLDR
  territory→timezone 표를 들여와야 해서 지금은 각주로만 적어 두었다.
- **`types` 가 `Public` 인 항목만 담는다.** Nager 의 `Bank` · `Observance` ·
  `Optional` · `School` · `Authorities` 는 뺐다. 그래서 미국의 Lincoln's Birthday 는
  없다.
- **지역 한정 공휴일은 넣되 표시한다.** `global: false` 인 항목(미국 Good Friday 처럼
  일부 주만 쉬는 날)도 목록에 넣고, "일부 지역 N곳" 배지와 지역 코드를 함께 적는다.
  오늘이 그런 날뿐이면 카드도 "일부 지역만 쉽니다" 로 바뀐다.
- **이름 축의 한국어 라벨 60개는 손으로 적은 것이다.** 사실(어느 나라가 언제 쉬나)은
  전부 파생되지만 라벨은 아니다. 틀리면 화면에 보이는 종류의 고장이라 검사에 걸지
  않았다 — 대신 문턱을 새로 넘는 이름에 라벨이 없으면 생성기가 멈춘다.
- **이름 축은 표기로만 묶는다.** `Labour Day` 와 `Workers' Day` 가 따로 서 있고,
  그래서 "노동절에 쉬는 나라" 를 찾는 사람은 두 장을 봐야 한다. 뜻으로 묶으면 한 장이
  되지만 그 판단이 어디서도 검사되지 않아서 그러지 않았다.
- **국기 두 개가 무겁다.** 세르비아 180 KB · 볼리비아 109 KB — 국장이 든 국기다.
  20×15 에서는 보이지 않는 세부인데 줄일 수단이 없다(래스터라이저가 없다).
  `gen-flags` 가 100 KB 넘는 것을 찍어 주므로 조용히 이고 있지는 않는다.
- **글꼴 조각 검사는 주석의 글자까지 센다.** `public/` 을 통째로 훑어 쓰는 글자를
  모으는데 CSS·JS 주석도 파일 안이라 함께 걸린다. 주석에 새 음절을 쓰면 그
  글자만을 위한 조각을 받게 되므로, 실제로 그런 일이 나면 문구를 바꾸는 편이 낫다.
- **음력은 한국 기준 한 벌뿐이다.** 중국 농력(UTC+8)과 하루 어긋나는 해가 있고
  영어 페이지도 KST 표를 본다. 각주로 적어 두었다.
- **순위 페이지의 "쉬는 날짜" 는 국가 페이지의 "공휴일 N일" 과 세는 단위가 다르다.**
  저쪽은 자료 건수, 여기는 날짜 수다. 페이지마다 각주로 밝혀 두었다.
